# Test Strategy

Deterministic by construction: injected clocks everywhere; no paid models; unit/integration/property/web/TUI suites use no sleeps — the real-host runtime E2E additionally uses fixed `settle()` pauses where the host's own retry/grind timing cannot be observed conditionally (polling is used wherever a condition exists).

## Layers

1. **Unit** — every module in PLAN Step 1–4; 100% statement/branch/function/line coverage gate on first-party code (ADP-037). No blanket excludes; entrypoints (`index.ts`, `tui.tsx`, `gui.tsx`) are covered through wiring tests, not excluded. The TUI footer status chip is unit-covered at the wiring level (both slots registered, dispose, settings-changed refetch) plus the pure `chipFor` label/color mapping; a PTY E2E journey may assert the rendered chip later.
2. **Property / state-machine** — `fast-check` (ADP-038): classification totality; health-state legality; scheduler invariants (unavailable/incompatible never selected; availability failure never escalates; observe≡active decisions; observe never changes execution; pin wins; no silent downgrade; finite budgets terminate; one half-open probe; preferred resource returns only at a safe boundary); receipt no-secrets/boundedness.
3. **Integration** — real seams with fake adapters: scheduler→health→state; retry hook policy→adapter; rpc validation; settings migration; restart round-trips; fail-open (throwing dependencies → defer).
4. **Fault injection** — deterministic provider fixture + clock: 429, quota reset, 503, timeout, disconnect, malformed error, context overflow, auth failure, recovery-after-N, concurrent sessions, child-session failure, OpenCode restart, Adaptive internal exception.
5. **Packed-plugin** — `@coool/opencode-plugin-test` packed mode against real isolated OpenCode hosts: targets 2.2.1, current, latest; surfaces server/rpc (the `tui` surface is not declared — the interactive TUI cannot be driven by the packed-plugin harness; the TUI journeys run in the Termwright E2E layer below); behavioral scenarios (first-install defaults, settings round-trip via rpc incl. invalid-patch rejection, status mirror, receipts.list, unknown-method rejection, host session API still works) — not just "plugin becomes active" (ADP-040).
6. **Server E2E (real host + fake provider)** — runtime scenario list below (ADP-041).
7. **Web E2E (Playwright)** — real OpenCode Web UI + built workspace plugin; Chromium + WebKit; desktop + narrow viewports; semantic locators; zero retries; screenshot checks as secondary assertions (ADP-042).
8. **TUI E2E (Termwright)** — real PTY; 80x24 (narrow floor) / default / wide; condition-based waits only; failure artifacts captured (ADP-043).
9. **Cross-surface E2E** — Web→TUI and TUI→Web settings sync (ADP-044).
10. **Headless** — full active (control) recovery flow with no UI surface loaded (ADP-045).

## Runtime E2E scenarios (ADP-041)

Real-host coverage (`test/runtime-e2e/` against `opencode serve` + the fake provider; supervision, routing, lifecycle, rpc, capacity, session-mode, tier-request files, plus `failure-modes` (timeout 408, mid-stream disconnect, malformed stream, 401 auth: never escalate, no retry loop), `durability-and-modes` (restart durability, OFF inert, pin precedence, live mode switch) and `manual-and-budget` (manual model pick wins, single-count breaker, per-task escalation budget)):

Quick routing, Standard routing, Advanced routing, agent-tier hint (warm-up + warm session) and explicit pin override (routing); observe mode, active mode, observe≡active decision parity (supervision); same-tier fallback, short throttling + Retry-After (supervision quota/rate-limit flows); provider outage, circuit breaker, single half-open probe, parking before dispatch (lifecycle breaker; supervision parks); tier escalation on context overflow (lifecycle 413 → escalate → owned continuation); quota exhaustion and its native-retry exemption (lifecycle); restart while parked, resume after recovery (lifecycle persisted-parked restart); wake after quota reset — every tier model out of quota parks the session, `status.get` lists it as waiting with its resume time, and it continues once without a user prompt when a quota window ends, exactly once with the plugin loaded twice, and after a host restart (wake.test.ts); durable tool side effects through owned recovery without replay (lifecycle marker file); multiple concurrent sessions (supervision); subagent children supervised as their own units (lifecycle subagent); user cancellation never fails over (supervision); fail-open on corrupted persisted settings (routing); headless execution (every scenario runs on bare `opencode serve` with no UI surface — ADP-045 by construction); RPC surface defaults/persistence/validation/receipts (rpc); durable health — a failed turn marks the tier resource windowed and the status surface shows it across the host's plugin-reload double-instance behavior (TUI health journey; health records persist through the storage seam and are rebuilt from storage on setup, per ARCHITECTURE.md "Stateless in memory"); per-session mode override — global observe, one session overridden to active via RPC answers with an applied admission while a fresh session stays observe-only, and clearing the override returns the session to the global mode (rpc + supervision; ADP-054); tier requests — the agent declares a task tier through the plugin's adaptive_tier tool and the NEXT admission in the same session routes into the requested tier's resource, while a request for an unconfigured tier defers with tier-not-configured and the session keeps running on its own model; sensed capacity — a completed turn whose response carries x-codex usage headers surfaces in `status.get` as usedPercent/resetAt for the configured openai resource (capacity.test.ts; ADP-056); tier requests over the RPC surface — tier-request.set pins one session's next admissions to a tier while a second session keeps the ordinary ladder, clearing with null restores it, and an unknown tier or malformed wire input is rejected without a write (ADP-055).

Documented limitations (minimal proofs per GOAL):

- **Draining** is unit-covered only: the drain health event has no runtime emitter in the host wiring (verified by source search); no runtime trigger exists.
- **Variant/effort escalation** is unit-covered: escalating at runtime requires a model inventory entry with a variant ladder; the fake provider's host config exposes none, and strength is never guessed from variant names (ADP-004).
- **Native `/goal` through a mid-goal model transition** is impossible on host 2.2.5: goal auto-continuation turns run inside one execution unit with no prompt hook and no execution boundary between them; the lifecycle /goal test instead proves the GOAL.md flow (goal starts → preferred fails → veto → owned recovery continues the goal on the fallback → completes → preferred again at the next boundary) and records the limitation.
- **Compatibility-gate demand is empty in production**: the host exposes no per-episode demand source (tools/modalities/context tokens) in the v2 wiring, so runtime admission passes `demand: {}` and only the `model-unavailable` dimension can fire live; the remaining gate dimensions (tools, modalities, context capacity, variant availability) are exercised at the unit layer (`checkCompatibility` tests). The `drain`/`reset` health-event kinds are likewise requirement-driven surfaces with no runtime producer; capacity signals flow through `CapacityRegistry` directly.
- **Auxiliary-request tiering is unwired**: the priority ladder and the core honor auxiliary→`quick`, but the v2 host wiring has no source for it (auxiliary `model.request` kinds are observed but not routed separately — switching for an auxiliary request would move the primary model). Covered at the unit layer (`resolve.test.ts`). Explicit tier requests are wired through the `adaptive_tier` tool and the `tier-request.*` RPC (ADP-055).
- **Before-dispatch parking defers to OpenCode**: when a required tier has no usable resource at admission time, the scheduler emits `park`, but the wiring records the decision as a receipt and lets the episode proceed on OpenCode's own model (fail-open; the host's own selection is not overridden). Persisted parked records arise from owned-recovery failures and terminal quota exhaustion of every tier model, and are resumed at idle boundaries or by the wake timer; the restart/resume journey is proven in `lifecycle.test.ts`.
- **Prompt overhead**: the plugin sends exactly one fixed continuation prompt and nothing else — `test/execution/continuation/execute.test.ts` property-proves every owned prompt is `CONTINUATION_PROMPT` and a generated original never appears, so receipts and operational metadata cannot reach a prompt; routing CPU overhead is bounded by `test/core/scheduler/perf.test.ts` (ADP-052/053).
- **Headless (ADP-045)** is covered by construction: every runtime E2E scenario runs against bare `opencode serve` with no UI surface loaded (`supervision.test.ts` declares ADP-045).

### Command startup regression: mixed-release process state

The 1.6.1 command outage escaped because the command journeys started isolated
hosts with only the current release. An older release can leave its process-wide
ledger behind when the host loads a newer copy. Reusing the incompatible shape
crashed server setup (`shared.healthResets.set`), removing `/web-adaptive` and the
RPC needed by `/adaptive`. The versioned ledger key fixes that collision.

`test/fixtures/stale-ledger` now publishes the older shape before Adaptive loads:

- `runtime-e2e/coexistence.test.ts` checks command registration, executes
  `/web-adaptive on`, and verifies both project-located RPC access and the
  resulting server state.
- `e2e-tui/tui.spec.ts` opens the actual invitation from the command palette,
  saves it, then reopens the menu and Status dialog via `/adaptive`, for both
  global and project-local installs beside the stale ledger.
- `e2e-web/command.spec.ts` runs every real composer journey beside the stale
  ledger on Chromium desktop/narrow and WebKit (menu discovery, status/help,
  mode changes and invalid arguments).

These suites use the built workspace plugin; the separate packed-plugin matrix
checks installed-package behavior. Fresh-host journeys remain covered by the
other runtime, TUI and web specs. Runtime boot failures now include host plugin
load errors, not just the often-empty stderr stream.

The sandbox project path is canonicalized to match the host's cwd. On macOS,
using the `/var` temp-directory alias instead of `/private/var` made located GUI
RPC calls fail despite healthy host-default RPC. The located-RPC assertion also
guards this harness failure.

## Web E2E journeys (ADP-042)

Real-web coverage (`test/e2e-web/web.spec.ts` via `npm run e2e:web`: Playwright against the real OpenCode v2 web app served by `opencode serve` with the built workspace plugin on an isolated host; Chromium desktop, Chromium narrow 390x844, WebKit; zero retries):

Password connect → home empty state; wrong password → error state (stays on the form); keyboard-operable connect (pressSequentially + Enter); server disconnect kills the host process (own host per test) and the app surfaces the loss visibly — the next server round-trip produces the SPA's application-error screen on 2.2.5 (host-UI behavior, pinned so it can never regress to silence); settings page reachable and renders at every viewport width (narrow reaches Settings through the banner Tabs dialog); documented settings tabs visible; models catalog search finds the configured model and shows its empty state for unknown models; Extensions → Plugins lists `coool.adaptive`; plugin RPC integration from browser page context (settings.get observe default on first install, settings.set active → reload → persistence → back to observe, invalid patch rejected at the schema gate, status.get mirroring mode/tiers/receipts).

Documented limitations (minimal proofs per GOAL):

- **Plugin GUI surfaces** (open Adaptive settings, mode switch, health/status/quota/draining/unavailable/recovery displays, receipts preview) cannot load on any shipped host: the web SPA (2.2.5) mounts plugin GUI contributions only through the desktop-shell bridge (`bridge.pluginGuis()`), never fetches `/api/plugin/gui?id=…`, and `/api/command` lists only native commands; the desktop app's renderer build (1.15.4 and current 1.19.5, verified by asar archaeology and a live probe) ships neither the plugin-GUI SDK nor the bridge. The canary test asserts the absence so a future host that mounts plugin GUIs fails the canary and the journeys get implemented; the settings features themselves are fully covered through the TUI journeys (above) and the typed RPC (Web E2E). Desktop apps older than 1.19.5 additionally reject the `plugins` config key outright. Visual inspection note (T-31): on disconnect the host SPA disables actions ("Add project" greyed) without an error banner — host-UI behavior on 2.2.5, not Adaptive-owned.
- **Web command** (`test/e2e-web/command.spec.ts`, ADP-034): the browser app lists server commands in the composer's slash menu, so `/web-adaptive` is the web way to see and switch the mode. The spec drives the real composer (own host per project run, sessions created through the API and opened by URL so it works at narrow width) at desktop, narrow and WebKit: the slash menu entry, the status with its help lines, `on`/`off` switching with the server state verified over RPC, and the usage reply. Empirical host facts it pins: a `synthetic` message with `resume: false` only reaches the timeline when it has a `description`, and each message renders as one truncated row inside a collapsed "Updates" group, so replies are posted one line per message.
- **Add model / model search / variants / reorder / remove** as web journeys: the host web settings expose only the model-catalog picker (search + visibility) and OAuth-managed providers; custom providers are "Manage in opencode.json" (file configuration, not a UI journey). Model search and its empty state are covered; catalog mutation journeys are not applicable to a custom-provider host.

## TUI E2E journeys (ADP-043)

Real-GUI coverage (`test/e2e-gui/gui.spec.ts` via `npm run e2e:gui`): host 2.2.5's browser-served web app never mounts plugin GUI bundles (see the Web E2E canary), so the GUI plugin is driven through a minimal stand-in GUI host (`test/e2e-gui/standin.ts`: dialogs, toasts, sessions, servers/model catalog, `ui.Dialog`/`ui.Button`, jsdom) wired to a REAL OpenCode server — the real typed client, the real Adaptive RPC and a real model catalog. Every journey runs twice, once against `src/gui.tsx` (V8 coverage attribution) and once against the built `dist/gui-experimental.cjs` loaded through a `require` shim (the bundle has no sourcemap), so the shipped artifact is held to the same behavior. Journeys: first-run invitation; empty and populated Status (alert, table, Close button, Escape); the models editor (add with and without a variant step, move to top/up/down, remove with confirm yes/no, Escape at every level); global mode switch persisted; per-session mode and tier request on Home (explained) and inside a real session (set, no-op, clear); pin; receipts from a real turn and a seeded 32-receipt history (paging and every decision/outcome wording); the settings page (status rows, mode change through the server, live `settings-changed`). Fault injection wraps the real client (`interceptRpc`) to cover rejected writes (`{ok:false}`), failing reads, plain-object/bigint/string rejections, degraded health/window/breaker/pin snapshots, a failing or missing model catalog, a flow-level failure and the settings page's disconnected state. `src/gui.tsx`, `src/ui/gui/**` and `src/ui/flow/**` must reach 100% statements/branches/functions/lines in this suite on its own (`vitest --coverage` thresholds in `test/e2e-gui/vitest.config.ts`).

Real PTY (Termwright) against the real OpenCode TUI + fake-provider sidecar, with the built workspace plugin mounted (`npm run e2e:tui`). The menu was reworked around nouns with dynamic descriptions (title `Adaptive (<mode>)`; entries `Status`, `Models`, `Mode`, `Tier`, `Pin`, `Receipts` — Status first and suggested in the palette), the operating mode vocabulary is `off | observe | active` (persisted `control` values migrate on read), and a footer status chip (`Adaptive · <mode>`) renders in both footer slots and tracks `settings-changed` live. The Status page is one column-aligned table (header row, then one row per model in tier order — priority order within tiers — with MODEL / TIER / HEALTH / STATE columns rendered through a custom full-width dialog); the old per-resource drill-down was removed. Journeys: boot/first-run state (empty editor, configured model active, chip visible); keyboard-only command-palette navigation with Escape/cancel; the `/adaptive` dialog flow driven end-to-end from the palette — first-run invitation confirmed, the follow-up "Open the menu now / Later" select, the Status page (empty state on a fresh install), the observe→active mode switch with persistence (the Mode menu on EVERY screen first asks which mode to steer — `Global mode…` or `This session…`; picking `This session` on home is explained by an alert — "This session's mode can only be changed inside a session. Open a session and run /adaptive from there." — and the target question repeats, re-opening shows no invitation and the menu title reads `Adaptive (active)`), the receipts empty-state alert, and Escape cancellation at every dialog level; the same flows entered through the editor slash menu (`/` → Enter opens the invitation — the slash menu lists `/adaptive`, though typing the full word races the slash filter); the models editor — model search over the host catalog, add through the picker (incl. the variant step), "Settings saved", persistence re-verified by reopening the editor; Move to top / Move up / Move down with the editor list re-asserted; Remove with its confirm dialog plus the Escape-cancel path keeping the resource; pin set → status shows the pin → clear via "No pin" → `pin: none`; a full session turn through the provider; the receipts dialog showing the recorded decision after a real turn (`defer: routing-defer — tier-not-configured` in observe mode) with the plain-language "What happened:" detail; the off mode switch with the menu title reading `Adaptive (off)`; the per-session mode override (ADP-054) — after a completed turn the command runs inside that session, the mode target select offers `Global mode…` / `This session…`, the session list shows `Follow global (observe)` first with the inherited mode marked `(current)`, picking `active` retitles the menu `Adaptive (active)` across a close/reopen cycle, and the Follow global row still names the untouched global `observe` on re-entry; the status display — a quota-failed turn marks the tier resource and the Status table lists it in its tier group with the `[…, windowed]` state and the window deadline; the table dialog is widened to xlarge (`dialog.set`) so rows render on one line, styled to match the host's own dialogs (bold title, dim `esc` hint in the title row's right corner; the host panel's own inset provides the top spacing and a blank spacer row separates title from table — probed against the receipts dialog's rendering), and the journey asserts the full unwrapped row; the receipts browser seeded past one page (25 receipts planted in the sandbox's plugin storage between two boots) pages forward via "Next page" and back via "Previous page" to the first page; the reconnect journey — the background service daemon is killed, the TUI reports the lost transport (transient `ECONNREFUSED` banner) instead of exiting, and a subsequent turn completes through the restarted service; dimension runs at 80x24 (the narrow floor), the 100x30 default, and 200x50 wide. Validation errors are not a TUI journey: every TUI flow produces a valid patch by construction (picker selections, within-tier dedupe), so the "Invalid settings" alert is unreachable through pure UI — input validation is proven end-to-end by the web invalid-patch journey (schema-gate rejection from inside the browser page) and at unit level. Backspace does not navigate host select dialogs — Escape is the only close key (probed on 2.2.5). A synthetic "Back" footer action bound to Backspace was implemented and then removed: the host dispatches bound actions BEFORE the query input, so the binding swallowed the keystroke even when the query had text (one Backspace with "fa" typed closed the dialog instead of deleting a char, and a query-aware guard could not fix it — the no-op action still ate the keystroke, leaving typed filters undeletable). A canary journey asserts the menu stays open on Backspace; if a future host lets Backspace reach plugin handling, it flips and Backspace-as-back can be reintroduced. Capacity journey (ADP-056): with a `openai/probe-codex` resource configured in Standard and a completed turn whose fake-provider response carries `x-codex-primary-used-percent: 72` / `x-codex-primary-reset-after-seconds: 900`, the Status table shows `used 72%, resets HH:MM` in that row's STATE column — read from the persisted capacity mirror, because the TUI host loads the plugin twice and the instance serving `status.get` never sees the response headers itself. The footer chip is unit-covered (slot registration, dispose, live refetch, `chipFor` color mapping); the journeys anchor on the same surfaces it reads.

Requirements the TUI RPC under test imposes on the sandbox (both established empirically on 2.2.5 after the earlier "TUI does not load plugin TUI bundles" limitation was falsified — its real root causes were two Adaptive-side bugs, since fixed):

- Both global and project-local installs are exercised. RPC calls must carry the TUI location; missing location caused the earlier project-local `rpc.unavailable` failures.
- Boot waits for the configured fake model as well as the home prompt. On 2.2.7 the prompt renders first; submitting before model readiness opens host sign-in. The fake-provider turn regression failed under Node 24 before this condition-based readiness fix and passes after it.
- The plugin's keymap layer must register with `mode: "global"` (`src/tui.tsx`); the default input-mode scoping kept the palette from matching the command.
- The keymap layer registers asynchronously some seconds after the boot prompt, so the suite retries the palette match. The reliable slash path is `/` followed by Enter (typing the full `/adaptive` word races the slash filter).

## Cross-surface sync E2E (ADP-044)

`test/e2e-web/sync.spec.ts` (part of `npm run e2e:web`, all three browser projects) proves the server is the single source of truth in both directions against one shared real host:

- Web → other surface: a settings change made from the real web app arrives live on a second typed client — the `settings-changed` event is observed on the host event stream and the client's `settings.get`/`status.get` reflect the change.
- Other surface → Web: a settings change made by the second typed client is observed live (`settings-changed`) and visible in a freshly loaded web app (`settings.get` and `status.get` mirror it) — no surface-local settings state anywhere.

Surface fidelity (both limitations are proven by canaries, not assumed): the web side speaks the plugin RPC from inside the page because the plugin GUI does not mount in the browser-served app (Web E2E canary above); the second client is bound to the exact RPC definition `src/tui.tsx` binds (`context.client.rpc(adaptiveRpc)`) because driving two interactive TUIs in one automated test is not automated — the TUI's own RPC path is covered for real by the Termwright journeys above. Subscription liveness is proven before each journey with a same-value probe patch (a valid no-op patch still succeeds and emits) — no fixed sleeps.

## Deterministic fake provider (ADP-039)

Local OpenAI/OpenCode-compatible HTTP+SSE server scripting: success, streaming, tool calls, partial execution, 429 (+Retry-After), quota/reset headers, 503, timeout, disconnect, malformed response, context rejection, recovery after N calls. Real OpenCode talks to it in E2E; unit/integration layers use in-process fakes typed against the same shapes.

## Traceability (ADP-047)

- Test files, plugin-test scenarios, `vitest.config.ts`, CONTRIBUTING.md, and release scripts declare coverage with a `covers: ["ADP-xxx"]` literal (above the first import).
- `npm run traceability` (`scripts/traceability.ts`) parses `docs/REQUIREMENTS.md` headings and fails on: an unknown ADP id (typo gate), a requirement with no declaring files, or an E2E-applicable requirement that no E2E file (runtime-e2e / e2e-web / e2e-tui / plugin-test) declares. Requirements that are inherently unit-level carry an explicit `NOT_E2E_APPLICABLE` exemption with a why-comment inside the script (safe default: applicable). The report lands in `test-artifacts/traceability.json`.

## Coverage (ADP-037)

Vitest + V8 coverage, thresholds 100/100/100/100 on first-party `src/**`. Only genuinely generated/vendor code may be excluded, clearly identified. No `istanbul ignore`, no empty tests, no implementation-trivia assertions. `npm run coverage` runs the `unit` project only: real-host runtime E2E under V8 instrumentation is pathologically slow and timing-flaky (receipt polling against an instrumented host), and `src/**` coverage is complete from the deterministic suite alone; runtime E2E still runs in every `npm test` and in `verify:release`.

## Packaging and release gate (ADP-048/050)

- `npm run pack:check` (`scripts/pack-check.ts`): builds a real tarball with `npm pack`, inspects it — required entrypoints (`dist/index.js`, `dist/tui.js`, `dist/rpc.js`, `dist/gui-experimental.cjs`, their `.d.ts`, `LICENSE`, `README.md`, `package.json`), forbidden content (`src/`, `test/`, `docs/`, `scripts/`, `node_modules`, `GOAL.md`, `coverage/`), manifest fields (name / semver version / MIT) — then runs `npm publish --dry-run`. Report artifact: `test-artifacts/pack-check.json`. The static publish contract is additionally asserted in `test/package.test.ts` (exact exports key set, MIT, minimal runtime dependencies).
- `npm run verify:release` (`scripts/verify-release.ts`) runs the whole chain in one command, aborting at the first failure: format:check → lint → lint:biome → typecheck → test → coverage → build → pack:check → plugin-test → e2e:gui → e2e:web → e2e:tui (Node 22/24 PATH prefix on newer runtimes, macOS-only PTY) → traceability.

## Regression policy (ADP-046)

Every behavioral bug: failing-first test → fix → wider suite → keep test forever. Enforced in CONTRIBUTING.md and applied throughout the project including the final adversarial review.

## Flakiness rules

Zero retries in E2E; a flaky test is a bug (regression-test it or fix the nondeterminism); all waits are condition-based (`session.wait`, Termwright `wait_for_idle`, Playwright auto-waiting).

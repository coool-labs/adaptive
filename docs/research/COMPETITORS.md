# OpenCode Model-Routing / Failover Plugins — Competitive Research

Scope: facts that materially affect implementation of an OpenCode v2 model-routing/failover plugin
("Adaptive"). Hook names, API surfaces, error-classification strategies, and pitfalls. No marketing.

## Per-project notes

### 1. marco-jardim/opencode-model-router (GPL-3.0, 147★)

- **What**: Injects a compressed task→tier delegation protocol (fast/medium/heavy subagents) into the system prompt on every message; orchestrator LLM decides delegation. Budget modes, presets, provider fallback chain, read-only tier enforcement, verification/enforcement layer.
- **Mechanism**: Prompt injection via `chat.params`-equivalent system-prompt mutation + router-defined subagents; tier `effort`/`variant` applied per turn through the v2 `session` context hook (fills only keys not already present); v2 uses native `subagent` tool for child sessions; provider fallback is _instructed_ ("Err→retry-alt-tier→fail→direct") not enforced.
- **Adaptive takeaways**: Cost-ratio signal in prompt; tier = {model, variant, effort, costRatio}; overrides-file layering (global → project, deep-merge, drop-only-invalid-layer); validate tier models against the live catalog (`/router models` pattern, models.dev + configured providers).
- **Pitfalls**: GPL — never copy code. ~3.2–6.4K chars overhead every message. LLM-instructed routing is non-deterministic. Host-enforced read-only tiers required explicit permission engineering. `effort` only maps for Anthropic (needs helper plugin) and OpenAI (caps xhigh→high); dropped with warning elsewhere.

### 2. youngbinkim0/opencode-fallback (MIT, 40★)

- **What**: The most mature v2 failover implementation. Error-driven model fallback with per-agent chains, TTFT timeout, cooldown/auto-recovery, compaction fallback, foreground-subagent task replacement, v2 CLI toast companion.
- **Mechanism (v2, from `v2.ts`)**: registers `ctx.session.hook("context")` (starts TTFT window, tracks model/agent per session), `hook("model.request")` (tags request kind: primary/compaction/title), `hook("retry")` (returns `{retry: false}` to take ownership when a fallback is planned; else lets host retry), `hook("prompt")` (auto-recovery to original model when out of cooldown, respecting manual switches), plus `ctx.event.subscribe()` for `session.step.started/failed`, `session.execution.failed/interrupted/succeeded`, `session.text.delta` etc. Dispatch sequence: plan → `ctx.session.interrupt` → **`ctx.session.wait`** → re-check model inventory → `ctx.session.switchModel` → commit → `ctx.session.prompt({resume:true, metadata:{[PLUGIN_NAME]:true}})`. Own prompts are recognized via metadata to avoid re-triggering. Event-location filtering by `event.location.directory`/`workspaceID`. Model candidates filtered against `ctx.model.list()` enabled inventory (30s TTL).
- **Adaptive takeaways**: This is the reference implementation of the v2 interception pattern. Copy the shape: context hook for TTFT + tracking, retry hook for ownership, event stream for settling detection, wait-before-switch, metadata-tagged continuations, inventory-gated chains.
- **Pitfalls**: Never `session.wait` inside the retry hook itself (host must finish failing; stream must keep draining). Idle from the OLD execution can arrive after new admission — compare timestamps. Interrupt/`execution.interrupted` accounting needs an `expectedInterrupts` counter. Reload/generation identity (`buildID`/`generationID`) needed to reason about hot reloads. Cold restart loses in-memory background delivery jobs.

### 3. alvinunreal/oh-my-opencode-slim (MIT, 10k★)

- **What**: Multi-agent orchestration suite (Orchestrator/Explorer/Oracle/etc.) with per-agent model presets, runtime `/preset` switching (v2 session-scoped preset apply, no restart), background subagent delegation, keyword-triggered Council mode with lazy prompt injection.
- **Mechanism**: Agent preset config → subagent registration; v2 `/preset` applies subagent inference settings to current session via session hooks; lazy hook injection (`council-inject` runs once per session on trigger; `disabled_hooks` opt-out).
- **Adaptive takeaways**: Lazy, trigger-based prompt injection (zero tokens when unused); runtime preset switching scoped to session vs global-default distinction; project-config inheritance walking ancestor `.opencode` dirs.
- **Pitfalls**: Not a failover plugin — no error interception. Heavy prompt/agent surface. Session-scoped vs global preset state confusion is a documented user pain; model/preset state must be per-session and clearly surfaced. Note `experimental.subagent_depth` gating for nested subagents on v2.

### 4. azumag/opencode-rate-limit-fallback (MIT, 23★)

- **What**: Rate-limit detection with fallback modes (`cycle`/`stop`/`retry-last`/`wait`), circuit breaker, metrics, dynamic model prioritization, config hot-reload, headless (`opencode run`) policy, subagent-depth-aware fallback.
- **Mechanism (v2)**: ordered `fallbackModels` chain; on rate-limit/transient failure the session is switched to the next model and retried ~1s later; chain exhaustion → mode decides (cycle back / stay / stop / never-switch wait); cooldown starts at `cooldownMs` and doubles per consecutive exhausted pass, capped at 1h, reset by next user prompt. Detection via `session.error`, `message.updated` errors, `session.status type:"retry"`.
- **Adaptive takeaways**: The four exhaustion modes are a good UX vocabulary; doubling cooldown with user-activity reset; provider-wide block awareness ("workspace-wide rate-limit errors skip other models on the blocked provider" — same idea as opencode-fallback); headless-mode policy knob (`ignore`/`abort`) for `opencode run`.
- **Pitfalls**: OpenCode stops retrying a turn after its own retry limit even if the plugin wants another try — must resume after failure, and never resume user-interrupted turns. Dynamic prioritization needs min samples before reordering (learning phase) or it thrashes. Pattern-learning below 0.7 confidence disabled at runtime (safety floor).

### 5. HyeokjaeLee/opencode-auto-fallback (MIT, 12★)

- **What**: Two-tier error classification (immediate vs backoff-retry), per-agent chains with per-entry generation params, large-context model switching (v1 only), agent-name normalization, auto-generated default config, plugin-order compatibility guidance.
- **Mechanism (v2 adapter, from `src/v2.ts`)**: `chat.params` → `ctx.session.hook("context")` (reapplies stored fallback params onto `event.options`: temperature/topP/maxTokens/reasoningEffort/thinking); errors → `ctx.session.hook("retry")` where the event is mutable: `{ retry: true, delay }` for backoff or `{ retry: false }` + `ctx.session.switchModel` + `ctx.session.prompt(continuation)` for fallback. Tracks original agent identity per session so re-sent prompts keep the agent. `session.model.selected` event detects manual switches and clears cooldown.
- **Adaptive takeaways**: The exact v2 retry-hook decision shape (`{retry:true,delay}` vs `{retry:false}`); applying per-model generation params through the context hook on the next request; respecting `session.model.selected` as the manual-override signal; agent-name normalization (strip whitespace/zero-width + lowercase).
- **Pitfalls**: v2 lacks `session.summarize`, `session.revert`, `session.messages`, and the compaction hook — large-context switchback, prefill recovery, and compaction injection are impossible on v2. Subagent (task-tool) children can't be aborted for recovery (abort cancels the parent's pending tool call). One-shot `opencode run` callers exit before continuation prompts can be delivered — need a persistent `opencode serve` + HTTP API for automated workloads.

### 6. linuxdynasty/opencode-quota-failover (MIT, 1★)

- **What**: Quota-exhaustion-only failover across providers (Anthropic → Bedrock → OpenAI) with tier-aware model mapping, global cross-session cooldown, 12 MCP control tools, strict two-tier quota signal classification.
- **Mechanism**: Subscribes to `message.updated`, `session.status`, `session.error`. `isDefinitiveQuotaError` (`insufficient_quota`, `billing_hard_limit`, 402+billing language, out-of-credits) fires immediately; `isAmbiguousRateLimitSignal` defers until the session stalls AND retry backoff ≥ 30min (`minRetryBackoffMs`). Queues failover until session `idle`, then replays last user message on next provider, mapping opus/sonnet/haiku via `modelByProviderAndTier`. Global `globalCooldownMs` prevents cascades across concurrent subagent sessions.
- **Adaptive takeaways**: The definitive/ambiguous quota split and the "what does NOT trigger failover" table (429 short-backoff, 503/overload, context-length-exceeded) is the best error taxonomy in the ecosystem; global cooldown across sessions; dispatch-failure diagnostics (Reason/Category/Hint); MCP tools for runtime inspection.
- **Pitfalls**: Provider-level failover (not model-level) means tier mapping must stay current — hardcoded catalogs rot. OpenAI failover dispatch fails if the user is ChatGPT-OAuth-authed but has no API key (auth vs billing confusion). Replaying the _last user message_ loses any assistant progress since (contrast with opencode-fallback's continuation-on-same-session approach — Adaptive should prefer the latter).

### 7. e-kotov/opencode-chatgpt-status (MIT, 0★)

- **What**: ChatGPT/Codex subscription quota display for OpenCode 2. Three zero-inference evidence sources: passive `x-codex-*` response headers, direct `chatgpt.com/backend-api/wham/usage` with OpenCode's ChatGPT OAuth credential, authenticated LiteLLM `GET /v1/chatgpt/usage` gateway endpoint.
- **Mechanism (from `src/server.js`)**: `ctx.session.hook("http.response")` parses `x-codex-*` headers (incl. LiteLLM `llm_provider-` prefixed form) per session; `ctx.integration.connection.active("openai")` + `.resolve()` reads the OAuth credential (OpenCode refreshes it — plugin only re-resolves, 401 retried once only if token changed); provider `baseURL`/`apiKey` read inside `ctx.model.transform` (config plugin registers after external plugins); gateway catalogue discovery triggered on `provider.updated`/`model.updated` events, cached in `ctx.storage`, applied via model transforms + `ctx.model.reload()`; TUI talks over `ctx.rpc.register` so credentials never leave the server.
- **Adaptive takeaways**: This is the blueprint for Adaptive's quota tracking. `wham/usage` returns windows (`5h`, `weekly`) with used% + reset times — directly usable to _proactively_ route away from an exhausted model before errors occur. Passive headers work for any provider that relays Codex headers and need no credentials.
- **Pitfalls**: OpenCode's built-in `openai` provider defaults to WebSocket transport on v2 → bypasses the HTTP hook entirely (passive headers unavailable there; direct polling still works). WHAM `primary` slot is weekly on some plans — label windows by reported length, not slot name. Don't refresh OAuth yourself; don't store credentials/account IDs; per-host throttle (60s) for usage polling. Plugin storage must be sanitized (an earlier version stored full provider templates incl. credentials — had to be scrubbed).

### 8. bulutmuf/opencode-failover (MIT, 51★)

- **What**: API-key rotation/failover across multiple keys per provider: weighted round-robin, quarantine with exponential backoff (60/120/240/300s cap), permanent disable on 401/403/402, `retry-after` parsing (ms/seconds/HTTP-date), LLM tools (`keychain-setup` etc.) + `/keychain` TUI dashboard.
- **Mechanism**: **Global `fetch` monkey-patch** (`fetch-patch.ts`) intercepts every request, identifies provider by existing Authorization header, swaps keys; response classifier decides quarantine/disable. State masked in `~/.opencode/failover-state.json`.
- **Adaptive takeaways**: retry-after parsing and the per-key classifier table (429→quarantine, 401/403/402→disable, 5xx→temporary, ResourceExhausted→2s) are directly reusable if Adaptive adds key rotation. Key masking and `.env` management patterns.
- **Pitfalls**: Global fetch patching is the anti-pattern — it's invisible to the host's retry accounting, can conflict with other patches, and bypasses v2's hook architecture. On v2, prefer provider-config/key injection through supported surfaces or at least the http hooks. Permanent disable on 401 misfires for expiring OAuth tokens.

## Hacklone/opencode-plugin-test — testing OpenCode v2 plugins

**What it provides**: CLI (`opencode-plugin-test`) + library (`runPluginTests()`) that tests a plugin the way a user's machine runs it:

1. Finds the plugin package → `npm pack` (the exact bytes npm ships).
2. Inspects the tarball: every `exports` target must exist (catches overzealous `files` fields, exports pointing at nothing).
3. Extracts, installs declared runtime deps, registers the artifact in a sandbox: a throwaway project with its own `opencode.json`.
4. Boots a real host (`opencode serve`) with a generated password; readiness = polling `GET /api/plugin` until the plugin list is non-empty (v2 has no JSON health endpoint).
5. Asserts plugin registers with `state: active` and declared surfaces (`server`, `tui`, `rpc`) registered; runs author-written scenarios against the live host via an authenticated `request()` helper; structured diagnostics (`PKG###`, `HOST###`, `API###`, `SCEN###`, `CFG###`, `ENV###`, `SYS###`); reporters pretty/json/junit; `targets: ["current","latest","2.1.2"]` to test against multiple OpenCode versions.

**How packed mode works** (`mode: "packed"`, the default): the tarball is materialized and registered **by extracted local path**, not via host-side npm install (ADR 0001) — v2 cannot load local artifacts through its `{package, options}` config form, so configured `options` reach the _scenario context_ (`ctx.options` in scenarios), **not** the plugin's `setup()` (ADR 0003). Sandbox runs with a from-scratch sanitized environment (fresh `HOME`/XDG, no inherited vars), so your real `~/.config/opencode` is never touched (ADR 0002).

**Adaptive use**: adopt as CI gate — pack-mode catches the exact failures that hit users: files missing from the tarball, broken exports, `setup()` throwing, RPC/TUI surfaces not registering, plus multi-version host regressions. Note for Adaptive's own options testing: verify options through scenarios observing plugin behavior, or ship a test provider entry in the sandbox `opencode.json`.

## fcoury/termwright — PTY TUI automation

**What it is**: Rust, Playwright-like automation framework for terminal TUI apps. Wraps any command in a PTY (80x24 default), exposes screen text/cells/cursor, wait conditions (`wait_for_text`, `wait_for_idle` = screen stability), input simulation (keys, hotkeys, typing, best-effort mouse), JSON output for agents, PNG screenshots. CLI (`termwright run|screenshot|run-steps|exec|hub|daemon`) and Rust library.

**Driving a PTY TUI test with it** (daemon mode is the right fit for OpenCode's TUI):

```bash
cargo install termwright && brew install socat jq
SOCK="/tmp/oc-test-$$.sock"
termwright daemon --socket "$SOCK" --cols 100 --rows 30 -- opencode &   # or: --background
while [ ! -S "$SOCK" ]; do sleep 0.1; done
tw() { echo "$1" | socat - UNIX-CONNECT:"$SOCK"; }
tw '{"id":1,"method":"wait_for_idle","params":{"idle_ms":500,"timeout_ms":10000}}'
SCREEN=$(tw '{"id":2,"method":"screen","params":{"format":"text"}}' | jq -r '.result')
tw '{"id":3,"method":"type","params":{"text":"fix the bug in foo.ts"}}'
tw '{"id":4,"method":"press","params":{"key":"Enter"}}'
tw '{"id":5,"method":"wait_for_idle","params":{"idle_ms":1000,"timeout_ms":60000}}'
tw '{"id":6,"method":"screenshot","params":{}}' | jq -r '.result.png_base64' | base64 -d > out.png
tw '{"id":99,"method":"close","params":null}'
```

Daemon RPC methods: `handshake`, `screen` (text|json), `screenshot`, `press`, `type`, `hotkey`, `wait_for_text`, `wait_for_idle`, `status`, `close`. `termwright run-steps <file.yaml|json>` runs declarative step files (supports `--connect` to an existing daemon socket, `--trace`); `hub start/stop` runs N parallel sessions. Emulates OSC 10/11/12 color queries and cursor-position requests (disable with `--no-osc-emulation`). macOS/Linux only, mouse best-effort.

**Adaptive use**: E2E tests that drive the real OpenCode TUI and assert on fallback toasts / status-line output; pair with `opencode serve` HTTP API for setup/teardown. For headless failure injection, mock providers (like opencode-fallback's `test:integration` harness: local OpenAI-compatible mock returning 429) remain the cheaper option; termwright covers the TUI-visible behavior.

## Cross-cutting implementation checklist for Adaptive (v2)

1. **Hook surface**: `ctx.session.hook("context")` (TTFT start, per-session state, apply fallback generation params), `hook("retry")` (ownership decisions `{retry:true,delay}|{retry:false}`), `hook("prompt")` (recovery + own-prompt recognition via metadata), `hook("model.request")` (request-kind tagging), `hook("http.response")` (quota headers), `ctx.event.subscribe()` (lifecycle events), `ctx.model.transform`/`ctx.model.list` (inventory + provider settings), `ctx.rpc.register` + `ctx.storage` (TUI/status surface).
2. **Dispatch discipline**: plan → interrupt → `session.wait` → re-verify inventory → `switchModel` → commit state → metadata-tagged `prompt(resume:true)`.
3. **Classification order**: structured SDK fields > HTTP status > curated patterns, with provider-scoped ignore lists for benign billing notices; quota vs rate-limit vs transient vs auth vs context-overflow as distinct classes.
4. **State**: per-session (model, agent, request token, timers) + per-model (cooldown, circuit, TTFT stats) + per-provider (global rate-limit block, quota budget from usage endpoints) + global failover cooldown to stop subagent cascades.
5. **Config**: validate model refs at load against live inventory; layered overrides (global → project, deep-merge, drop only invalid layer); hot-reload with validation and state preservation.
6. **Test**: `@coool/opencode-plugin-test` packed mode in CI against `current` + pinned versions; local mock providers for 429-after-tool-call, no-first-token, chain exhaustion; termwright daemon for TUI-visible assertions.
7. **Don't**: global fetch patching; LLM-instructed-only routing for failover decisions; abort/replay full tasks (use same-session continuations); v1-only APIs on v2 (summarize/revert/messages/compacting hook); refresh OAuth tokens yourself.

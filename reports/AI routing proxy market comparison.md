# Existing proxies route requests, not work

No tool on the market today (November 2026) works as a local, harness-agnostic version of opencode-adaptive. The availability side is crowded. **Claude Code Router (CCR)** has about 38k stars, ships a desktop app for macOS, Windows and Linux, and already lists OpenCode, Codex and Claude Code as clients. It offers ordered fallback, retries and credential pools. LiteLLM and Bifrost have mature fallback and cooldown machinery, and CLIProxyAPI and 9router track 5-hour and weekly subscription windows. All of them work one request at a time. Their fallback chains move work to stronger or weaker models without telling the user, and 9router degrades from Subscription to Cheap to Free by design. **No tool reviewed parks work durably and resumes it after a quota reset.** The longest wait found is CLIProxyAPI's 30-second default. No tool escalates on structured evidence, and none has an observe mode that shares the production scheduler. Hosted routers (OpenRouter Auto Code, Cloudflare, Requesty, Kilo) went the other way: they converged on LLM classifiers that read prompt content. The proxy form also has hard limits. It cannot wake a harness, tell a user cancel from a dropped socket, see manual model changes, or survive the harness exiting. A straight port of the plugin to a proxy would therefore lose its strongest guarantees. The design worth building is a **local supervisor daemon with thin per-harness adapters**, with a proxy data plane used only where a proxy is actually better.

## Five crowded camps all solve availability one request at a time

The market splits into five groups. Popularity sits with gateways and subscription pools, not with supervision.

| Camp                            | Representative tools (Nov 2026)                                                        | What they actually do                                                                |
| ------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Harness-agnostic local gateways | CCR (38k★, ~174k npm downloads/month), ccproxy, claude-code-mux (stale since Nov 2025) | Per-request routing rules, retries, fallback, credential pools, protocol translation |
| Subscription bridges and pools  | CLIProxyAPI (58k★), sub2api (46k★), 9router (32k★), claude-relay-service (13k★)        | Expose consumer subscriptions as APIs; rotate accounts across quota windows          |
| General self-hosted gateways    | LiteLLM (63k★), new-api (51.5k★), Bifrost (9.4k★)                                      | Fallback chains, cooldowns, load balancing, cost logs                                |
| Hosted routers                  | OpenRouter, Cloudflare AI Gateway, Requesty, Vercel, Kilo Gateway                      | Cross-provider failover plus classifier-based "auto" routing                         |
| OpenCode fallback plugins       | ≥8 packages, none above 40★; the largest has ~14.6k downloads/month                    | Per-agent fallback chains, cooldowns, some wait modes                                |

**CCR is the incumbent a harness-agnostic port would face.** It now calls itself "a local model gateway and control plane for coding agents". It supports Claude Code, Codex, Kilo Code, OpenCode, Pi and others through "Agent Profiles", which launch each CLI with isolated config pointed at the gateway on `127.0.0.1:3456` ([CCR README](https://github.com/musistudio/claude-code-router); [npm](https://registry.npmjs.org/@musistudio%2Fclaude-code-router)). It advertises "retries, credential pools, key rotation, and ordered fallback models" and "account status" in its logs. Its routing docs list failure triggers and global and rule-level fallback ([CCR routing doc](https://ccrdesk.top/en/routing)). Those docs are rendered by JavaScript and could not be extracted, so it is unconfirmed whether CCR separates quota errors from other failures or honors reset headers. That gap should be closed by reading CCR's source before committing to a positioning.

The subscription camp grows on cost arbitrage and account sharing. CLIProxyAPI's README is full of sponsors from paid "relay" resellers ([CLIProxyAPI README](https://raw.githubusercontent.com/router-for-me/CLIProxyAPI/main/README.md)). sub2api and claude-relay-service openly warn that use "may violate the terms of service of Anthropic" ([sub2api](https://raw.githubusercontent.com/Wei-Shaw/sub2api/main/README.md); [CRS](https://raw.githubusercontent.com/Wei-Shaw/claude-relay-service/main/README.md)). The general-gateway field is also churning. TensorZero was archived on 2026-06-12, Palo Alto Networks closed its Portkey acquisition on 2026-05-29, and Helicone moved to maintenance mode ([INFRO](https://infro.io/blog/who-owns-your-ai-gateway-2026)). On the hosted side, Stripe agreed to acquire OpenRouter ([HN](https://news.ycombinator.com/item?id=49364559)). Protocol coverage is now table stakes. LiteLLM, Bifrost, new-api, CLIProxyAPI, CCR and 9router all expose Anthropic Messages, and most also expose OpenAI Responses ([new-api](https://github.com/QuantumNous/new-api); [Bifrost](https://github.com/maximhq/bifrost)). A newcomer cannot win on translation.

## Every fallback chain silently crosses capability tiers

**Commercial auto-routing is now built on classifiers.** OpenRouter's Auto Router sends each request to "a fast decision model" that "rates eleven aspects of the request", then picks a model and reasoning effort within a price-defined `cost_tier` ([OpenRouter Auto Router](https://openrouter.ai/docs/guides/routing/routers/auto-router.md)). Requesty passes the first user message to a third-party decision model such as Typesafe Jev or Cloudflare Clef ([Requesty Auto Routing](https://docs.requesty.ai/features/auto-routing.md)). Cloudflare's `cloudflare/auto` classifies task type and difficulty ([Cloudflare Auto Router](https://developers.cloudflare.com/ai-gateway/features/auto-router/index.md)). Self-hosted tools follow the same pattern. LiteLLM has a complexity router with `SIMPLE`/`MEDIUM` tiers ([LiteLLM](https://github.com/BerriAI/litellm)), Plano uses a 4B routing model that is hosted by default ([Plano docs](https://docs.planoai.dev/guides/llm_router.html)), and vLLM Semantic Router has published an OpenCode "auto mode" ([vLLM-SR blog](https://vllm-sr.ai/blog/opencode-auto-mode/)). Every one of these sends prompt content to a decision model, so Adaptive's "no LLM classifier, no keyword soup" rule is now a real point of difference.

Three products come close to parts of Adaptive's routing model:

- **Kilo's `kilo-auto/frontier`** maps agent mode to model deterministically: plan and architect go to Opus, code and build go to Sonnet. This is essentially Adaptive's "supported role hint" rule, hosted ([Kilo Gateway](https://kilo.ai/docs/gateway/models-and-providers)).
- **OpenRouter Auto Code** "penalizes failures more harshly, so it course corrects faster when tests fail or the same error comes back" ([Auto Code](https://openrouter.ai/docs/guides/routing/routers/auto-code.md)).
- **NVIDIA Switchyard's `stage` algorithm** "scores the tool results already in the conversation… doesn't call a classifier" ([Switchyard](https://openrouter.ai/docs/guides/routing/routers/switchyard-router.md)).

The last two are the nearest analogues to evidence-based escalation, but both infer evidence heuristically from tool output. Neither takes an explicit, schema-validated request with a reason and evidence. Their "tiers" are also price buckets: Switchyard labels the cheapest candidate "efficient" and the most expensive "capable". They are not capability classes the user declares over their own providers.

**Fallback is where the capability/availability split breaks down everywhere.** OpenRouter's docs say "any error can trigger the use of a fallback model, including… Rate-limiting". Their own example falls back from Claude Sonnet to `gryphe/mythomax-l2-13b` ([OpenRouter Model Fallbacks](https://openrouter.ai/docs/guides/routing/model-fallbacks.md)). Vercel's example chains a frontier model to a nano model ([Vercel model fallbacks](https://vercel.com/docs/ai-gateway/models-and-providers/model-fallbacks.md)). 9router markets "Smart 3-Tier Fallback: Subscription → Cheap → Free" ([9router](https://github.com/decolua/9router)), and the OpenCode plugin chains fall back to free flash models ([azumag](https://github.com/azumag/opencode-rate-limit-fallback)). The closest any tool gets to Adaptive's error separation comes from three gateways:

- **Bifrost** has the most rigorous error taxonomy. A 429 rotates keys but still backs off. Exhausted quota (402, `insufficient_quota`) marks a key dead because "waiting can't refill an account". A cancelled caller means "Fallbacks do not run" ([Bifrost Retries & Fallbacks](https://docs.getbifrost.ai/features/retries-and-fallbacks.md)).
- **LiteLLM** sends context-window errors to dedicated chains that error out rather than spill into generic fallback ([LiteLLM Fallbacks](https://docs.litellm.ai/docs/proxy/reliability)).
- **CLIProxyAPI's** "quota" session mode keeps a session bound to its credential on transient errors and rebinds only on quota or auth errors ([config.example.yaml](https://raw.githubusercontent.com/router-for-me/CLIProxyAPI/HEAD/config.example.yaml)).

Users can approximate "stay in tier" by hand-curating LiteLLM order groups or Portkey's nested per-family chains. **No tool enforces it, refuses to borrow across tiers, or waits instead of downgrading.** That is the purpose of a fallback chain: always return an answer. Adaptive's invariant runs directly against it.

## Nobody parks work until the quota resets

Health tracking is common. Rigorous breaker semantics are rare:

| Tool                   | Breaker recovery                                                                                                                                      | 429 handling                                                                                              | Reset headers                                                                                                                    |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Portkey                | Closes after a cooldown timer (minimum 30s); no half-open probe ([Portkey](https://portkey.ai/docs/product/ai-gateway/circuit-breaker.md))            | Counted toward breaker trips in its example                                                               | —                                                                                                                                |
| APISIX                 | Active health checks                                                                                                                                  | Treated as unhealthy by default ([APISIX](https://apisix.apache.org/docs/apisix/plugins/ai-proxy-multi/)) | —                                                                                                                                |
| Kong                   | Target "reconsidered" after 10s; one success heals, effectively a passive half-open ([Kong](https://developer.konghq.com/ai-gateway/load-balancing/)) | —                                                                                                         | —                                                                                                                                |
| Bifrost                | Enterprise only: Healthy, Degraded, Failed, Recovering states                                                                                         | Rotate key plus backoff, not a dead key                                                                   | Deliberately **ignores** `anthropic-ratelimit-*-reset` ([Bifrost](https://docs.getbifrost.ai/features/retries-and-fallbacks.md)) |
| azumag OpenCode plugin | `halfOpenMaxCalls: 1` ([README](https://github.com/azumag/opencode-rate-limit-fallback))                                                              | —                                                                                                         | —                                                                                                                                |

The azumag plugin is the only tool that matches Adaptive's "half-open admits exactly one probe". Bifrost alone matches its rule that 429s don't trip breakers.

Quota-window awareness exists only in the subscription camp. 9router shows a "reset countdown (5-hour, daily, weekly)" ([9router](https://github.com/decolua/9router)), and CLIProxyAPI's ecosystem apps show "per-account codex 5h/7d quota windows" ([CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)). Both react to exhaustion by switching accounts or degrading, not by waiting. CLIProxyAPI's `max-retry-interval` waits at most 30 seconds by default for a cooled-down credential ([CLIProxyAPI config](https://help.router-for.me/configuration/basic.html)).

**Durable parking is absent from every tool reviewed.** Two things come close:

- **Claude Code's own auto-continue** (v2.1.234, August 2026) "waits in the open session and continues your task automatically when a claude.ai usage limit resets", without resending the last message ([AI Catchup](https://aicatchup.com/news/claude-code-desktop-auto-continue)). It covers one vendor, has no failover, and does not survive the process exiting.
- **opencode-runtime-fallback** continues the existing conversation on a backup model without re-sending the task. Its README admits it "loses this plugin's in-memory background delivery jobs" on cold restart ([npm](https://registry.npmjs.org/opencode-runtime-fallback)).

Codex users were still filing "Auto-Resume after Usage Limit" requests in late October 2026 ([OpenAI community](https://community.openai.com/t/feature-request-auto-resume-after-usage-limit/1397124)). The remaining stopgaps scrape the terminal and inject "continue" with tmux `send-keys` ([claude-code#35744](https://github.com/anthropics/claude-code/issues/35744); [claude-auto-resume](https://github.com/terryso/claude-auto-resume)).

Restoring the preferred model exists in weaker forms. LiteLLM keeps a session's pin while the pinned deployment is cooling down, "so the session returns to its deployment once it is healthy again" ([LiteLLM Routing](https://docs.litellm.ai/docs/routing)). That return happens on the next request, not at a safe boundary, so it can switch models mid-episode. The OpenCode plugins restore on "the next user prompt" ([azumag](https://github.com/azumag/opencode-rate-limit-fallback); [runtime-fallback](https://registry.npmjs.org/opencode-runtime-fallback)). That is closer to Adaptive's semantics but held only in memory.

The industry has independently converged on switching only at safe boundaries, though for prompt-cache economics rather than side-effect durability. Cloudflare pins a model "for an entire turn", Requesty pins per conversation, Copilot routes "along natural cache boundaries", and OpenRouter prefers changing reasoning effort over switching models ([Cloudflare](https://developers.cloudflare.com/ai-gateway/features/auto-router/index.md); [Requesty](https://docs.requesty.ai/features/auto-routing.md); [Copilot](https://docs.github.com/en/copilot/concepts/auto-model-selection)).

## A proxy sees requests; the plugin sees work units

**For Claude Code alone, a proxy can now see nearly everything the plugin uses.** Anthropic publishes a gateway protocol with these headers ([Claude Code gateway guide](https://code.claude.com/docs/en/llm-gateway-protocol.md)):

- `x-claude-code-session-id`
- `x-claude-code-agent-id` and a parent agent ID
- `x-claude-code-request-class`: `main`, `subagent`, `workflow`, `compaction` or `auxiliary`
- `x-claude-code-prompt-id`, shared by every request that serves one user prompt

Together these identify a work unit almost exactly. `compaction` and `auxiliary` map directly onto a deterministic quick tier. The catch is that the hint headers are **off by default behind a custom base URL**, so the user must set `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1`. An installer can do this with one write to `settings.json`, which running sessions pick up live ([env vars](https://code.claude.com/docs/en/env-vars)). For Codex, Gemini CLI, Cursor, Cline, Aider and OpenCode, no comparable published header contract was found. A proxy has to infer boundaries from the request body: a last message holding only `tool_result` blocks is a continuation, and anything else is a new turn. That is a structural guess, not a contract.

**Switching models mid-episode at the proxy is dangerous, not just expensive.** Thinking blocks carry signatures that must be "pass[ed] back unchanged" within a tool-use turn, and toggling thinking invalidates the prompt cache ([Anthropic: Thinking](https://platform.claude.com/docs/en/build-with-claude/thinking)). The auto-routing proxy UncommonRoute shipped "Invalid signature in thinking block" errors under Claude Code. It fixed them only by hard-locking each session to its previous model and failing closed when that model was unavailable ([UncommonRoute#20](https://github.com/CommonstackAI/UncommonRoute/issues/20)). LiteLLM drops encrypted reasoning on any cross-key fallback because the target "cannot decrypt" it ([LiteLLM Fallbacks](https://docs.litellm.ai/docs/proxy/reliability)). Mid-stream, a proxy can fail over transparently only before the first content byte. After that it must end the stream so the harness retries. Claude Code's `CLAUDE_CODE_DISABLE_NONSTREAMING_FALLBACK` exists precisely because proxy-induced fallbacks "produce duplicate tool execution" ([env vars](https://code.claude.com/docs/en/env-vars)).

**Parking is where the proxy form fails outright.** A proxy cannot wake a harness. It can only hold a request open, return a retryable error, or return a terminal one. Claude Code treats a `retry-after` above 60 seconds as fatal, and shows the error at once, unless the user enables `CLAUDE_CODE_RETRY_WATCHDOG`. With the watchdog on, it waits out the reset window ([gateway guide](https://code.claude.com/docs/en/llm-gateway-protocol.md); [env vars](https://code.claude.com/docs/en/env-vars)). Codex defaults to 4 request retries and 5 stream retries, and its built-in `openai` provider's retry count cannot be overridden ([openai/codex#3026](https://github.com/openai/codex/issues/3026)). Even in the best case the parked state lives in the harness process. Close the laptop or exit the CLI and the work is gone from the proxy's view.

| A proxy can                                                                                                                                                                                    | A proxy cannot                                                                           |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Share health and quota state across every harness and session                                                                                                                                  | Tell a user cancellation from a dropped socket or client timeout                         |
| Fail over between endpoints of the same model before the first byte                                                                                                                            | See a manual `/model` change as distinct from a config default                           |
| Parse `retry-after` and `anthropic-ratelimit-*` headers and classify errors (throttle, spend cap, 529 overload) ([Anthropic rate limits](https://platform.claude.com/docs/en/api/rate-limits)) | Wake a parked session after hours, or survive the harness exiting                        |
| Pin per-session model affinity using Claude Code headers                                                                                                                                       | Switch the harness's model so its UI, context window and effort settings stay consistent |
| Serve an escalation tool over MCP, if requests carry a session header                                                                                                                          | Resume from session state natively instead of hoping the client retries                  |

## Build a supervisor with adapters, not another gateway

The plugin's codebase already has the right seam. Its dependency rule keeps `core/`, `health/`, `execution/` and `state/` free of the OpenCode SDK, so the scheduler, breaker and parked-work store can move into a **local daemon** with a per-install bearer token, bound to `127.0.0.1`. Each harness then gets the thinnest adapter that captures its boundary signals:

- **OpenCode** keeps the existing plugin, which already has `session.wait`, `switchModel`, synthetic resume and the retry-hook veto. It becomes a client of the shared daemon.
- **Claude Code** gets an installer that writes `ANTHROPIC_BASE_URL`, `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` and `CLAUDE_CODE_RETRY_WATCHDOG=1` into `settings.json`, plus hooks for wake and resume and an MCP `escalate` tool that carries the reason-and-evidence schema.
- **Codex** gets a custom provider profile, because the built-in provider's retries are fixed.

The **proxy data plane stays deliberately narrow.** It does same-model endpoint failover before the first byte, captures quota headers, and enforces per-unit model affinity. It never rewrites the model inside a work unit. When a tier is exhausted mid-unit it parks and signals the adapter, instead of failing closed the way UncommonRoute does.

Position the product as an **execution supervisor, not a gateway**. Competing with CCR, LiteLLM or CLIProxyAPI on protocol translation and credential pools is a losing fight against 38k–63k-star projects that ship near-daily. The open ground is the set of guarantees none of them make:

- the capability tier never changes because of an outage;
- escalation is auditable, because it requires stated evidence;
- work survives a five-hour quota window and a reboot;
- the preferred model comes back at the next safe boundary;
- observe mode shows what control mode would do;
- nothing leaves the machine.

On that last point, none of the major gateways advertises local-only, no-telemetry operation, and every hosted auto-router sends prompts to a decision model. A sensible extension is to let the supervisor treat existing gateways (LiteLLM, CCR, OpenRouter) as ordinary user-configured upstreams. That makes it complementary rather than a rival.

Credentials must stay conservative. Anthropic states that using Pro or Max OAuth tokens "in any other product, tool, or service… is not permitted" ([The Register](https://www.theregister.com/2026/02/20/anthropic_clarifies_ban_third_party_claude_access)). It enforced this from April 2026, and OpenCode removed Claude subscription support after "anthropic legal requests". The defensible stance has three parts. Support API keys and cloud providers by default. Pass genuine Claude Code subscription traffic through **unmodified to the same Anthropic endpoint**, never re-routing it. Use OpenAI's official "Sign in with ChatGPT" program instead of lifting Codex tokens ([OpenAI Help](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites)). This matches the plugin's existing "only user-configured providers" invariant, and it keeps the product out of the pooling camp's ToS exposure.

Three market risks stand out:

- **Claude Code's native auto-continue and retry watchdog** already cover wait-and-resume for Anthropic subscription users. The unmet demand is cross-vendor, durable, and on Codex.
- **OpenRouter Auto Code** launched on 2026-11-06 ([OpenRouter](https://openrouter.ai/)). It will teach users to expect evidence-sensitive routing as a hosted default.
- **CCR could add a wait mode** at any time. It is unlikely to adopt tier integrity, though, because its fallback design assumes that always answering is the goal.

## Conclusion

The market reasons about the request and the price bucket. opencode-adaptive reasons about the execution episode and the capability tier. That difference is the moat, and it is exactly what a pure proxy throws away: a proxy only sees a work unit where a harness is willing to announce one. Today only Claude Code does, and only behind an opt-in flag. The harness-agnostic version is therefore a federation, not a proxy. One supervisor owns policy, health and durable state, and each harness contributes the boundary signals and the wake and switch powers only it holds.

The industry has already validated two of the plugin's bets. Vendors now pin models to turns or conversations, and they now escalate on failure signals. What nobody has validated is treating availability and capability as separate axes, so the user never trades correctness for uptime without knowing it. That is the claim worth building and marketing. Three questions remain open before committing: CCR v3's actual failure-trigger semantics (readable from its source), and the session headers sent by Codex and Gemini CLI, and whether OpenCode sends any to an external proxy (settled by capturing their traffic).
